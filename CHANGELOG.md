# Changelog

All notable changes to SharpeBench are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). One workspace
version covers every crate, the npm packages and the PyPI package. Sharing a
version is not the same as being published: the crates that reach crates.io
are the twelve listed in [RELEASING.md](RELEASING.md), and `xtask` and
`examples/reference-agent` are `publish = false`. Each section is one `v*` tag
and links the commits it was built from.

[Unreleased]: https://github.com/general-liquidity/sharpebench/compare/v0.25.0...HEAD

## [Unreleased]

### Breaking

- core: `sharpebench_core::SuiteEvidence` gains the public field `control_binding`, and `sharpebench_core::suite_controls` gains the public `ControlBinding`, `ControlDigest`, `UnboundField` and `control_preimage`, all re-exported from the crate root. A Rust struct literal over `SuiteEvidence`, or an exhaustive destructuring of it, must add the field, and a glob import gains the four names. `SUITE_CONTROL_INVENTORY` already declared which `ControlVerdict` fields the `run_provenance` digest covers, and declaring coverage is not the same as binding it: a reader holding the emitted evidence could see the claim that identity, intent and outcome are bound, and could not check that the row in front of them was the row that ran. `SuiteControlEvidence::binding` now computes that digest over the ordered per-control preimages the inventory itself defines, and publishes it beside the fields it covers and the one it does not, with `used_by_gate` recorded false on the record for the reason `SharpeDiagnostics` records it. The excluded `detail` line moves no digest, which is the reason the inventory states for excluding it, and the three non-finite residuals bind to three different digests where a digest over JSON would have written all of them as `null`. `ControlBinding` is `Serialize` only: a deserializable digest would be one an input document could assert rather than one this crate computed. No published number moves. The binding is reporting surface and never reaches the gate, eligibility or the rank; the committed golden score file is byte-identical, `sharpebench score --json` is unchanged, and the 40 artifact digests in `paper/evidence/provenance.json` are unchanged.
- core: `sharpebench_core::suite_controls::ControlError` gains the public variant `ControlBindingIncomplete { detail: PreimageError }`, so a `match` over that enum that lists every variant must add an arm. `suite_evidence` refuses rather than publishing a digest whose covered field set differs from the coverage statement printed beside it, which is what a disagreement between `SUITE_CONTROL_INVENTORY` and `control_preimage` would produce. No existing suite reaches it.

### Added

- cli: `sharpebench compare --axis <entrant|invocation|score-config> --baseline <checkpoint.json> --treatment <checkpoint.json>` declares a comparison between two sweep arms, or refuses it naming the field that decided it. `ComparisonReceipt::declare` shipped a release ago with no caller outside its own tests, and a comparability rule nothing runs declares nothing about a real comparison. The command reads the two checkpoints the resumable sweep already wrote, so the six identities it compares are the ones the arms actually executed under, and it writes to neither. Dataset, cost model and runner artifact stay undeclarable, so the thing that would void a comparison cannot be declared away: naming one of them as the axis is a usage error and nothing is emitted. A declared comparison exits 0 and names every identity checked equal to reach it; a refusal exits 1 and, under `--json`, is emitted as a document rather than printed to stderr where a machine reader would lose it. The receipt carries `used_by_gate: false` and is reporting surface beside a result: no score, gate, eligibility or rank sees it.

### Fixed

- llm field: the assembler reads the evidence it counts. `paper/evidence/assemble_llm_field.py`
  reconciles three kinds of accounting evidence and took each of the three
  counts off its file without reading a record: the attempt ledger's count was
  its nonblank lines, the statistics count was `rec.get("llm_calls", 0)` where
  `0 + True == 1`, and the comparison was over the totals. So a model's entire
  ledger replaced by `{` and a newline, or by `{}` and a newline, or its
  dispatch count stated as a JSON `true`, each reconciled against a real call
  and published the same field at exit 0 while all thirty assembler cases
  passed. Every ledger line is now parsed and required to be the record
  `reserve_call` writes, naming the request digest it was taken for, the model
  it was requested under, the scaffold version and the process identity, and a
  line reserving another model's request is refused rather than costed at this
  model's rate card. Every statistics counter is required to be present and to
  be a count, through the same `is_count` rule the token counts already went
  through, so a file that never stated `api_errors` no longer publishes a run
  as free of them. Equal counts are then held to be counts of the same calls:
  the ledger and the response cache both carry the request digest, so they are
  matched request by request, and an answer to a request nothing reserved no
  longer cancels against a reservation nothing answered. A retried request is a
  second reservation under one digest, which parts the counts, and the refusal
  there names the repeated digests so a retry is distinguishable from spend
  that bought nothing. These are false acceptances and not an observed
  undercharge: the LLM field has never completed, no `llm-field.jsonl` is
  published, and the 40 artifact digests in `paper/evidence/provenance.json` are
  unchanged.
- npm: the committed wasm bundle is rebuilt for 0.25.0. Every other version the
  release checks is a literal in a metadata file that the version bump rewrites;
  the one inside the wasm binary comes from `CARGO_PKG_VERSION` at compile time,
  so the bump left the committed bundle reporting 0.24.0 and the npm workflow
  went red on main at the release commit. The published v0.25.0 is unaffected:
  this release builds a fresh bundle before publishing, so what shipped was
  never the stale one and all seven release jobs passed.

### Changed

- docs: the regrade receipt is described as the library delivery it is. `sharpebench_sim::regrade_submission` has no production caller: nothing in this repository emits a `RegradeReceipt`, and the 2026-09-09 verification row claiming "every regrade linked to its source" was true of no regrade the repository performs. The row and the audit ledger now say so, and the reason it was not wired to `sharpebench rescore` is written down rather than left as an open seam a reader has to rediscover. A rescore's score comes from `verify_trajectory_strict`, whose per-run `steps.len() == end - start` check is exactly the condition `RegradeRefusal::FabricatedDecisions` names, so composing the two would either recompute the submission a second time and discard it, or move the published figure onto a second replay path; and the receipt's `original_evaluator` is historical, so a bundle that does not record it could only have it supplied by the operator, which replaces one trusted input with another rather than removing one. The source digest `RegradeRequest` takes on trust is still the value a rescore verifies, and the two still compose only by hand.
- release: the release now rebuilds the committed wasm bundle after the version
  bump, inside the release tree, and folds it into the version-bump commit. The
  bundle carries its own version compiled in from `CARGO_PKG_VERSION`, which the
  bump cannot rewrite the way it rewrites a literal in a manifest, so v0.25.0
  left the committed bundle reporting 0.24.0 and the npm workflow went red on
  main behind a correct publish. A pre-tag check cannot close this, because
  before the bump there is no version for the bundle to name. `wasm-pack` is now
  required to cut a release.

## [0.25.0] - 2026-09-12

### Breaking
- harness: `ModelGateway::open` refuses a money journal that holds a reservation with no settlement beside it, with `std::io::ErrorKind::InvalidData`, where it used to resume one. That record is what a gateway leaves when a settlement could not be written, and what a process that died mid-call leaves too. The condition that stops such a gateway, `journal_unwritable`, was a flag in memory initialised to `false` by `open`, so the operator action a stopped gateway invites, restart it, cleared it: the reopened gateway believed the journal writable and re-reserved budget against a total the file is known to understate, since the settlement that went missing may have priced above its reservation. The published spend was then lower than the real spend. Persisting the flag is not the alternative, because the condition is defined by a write to that journal having failed; what is already durable is the record, so that is what is read. An operator whose journal is refused reads it with `sharpebench gateway --journal <path>`, which reports `outstanding_usd_nanos` and `partial`, and runs what is left under a fresh journal. A journal whose records are complete resumes exactly as before.
- harness: `SpendState` gains a public `outstanding_calls` field, so a Rust struct literal or exhaustive destructuring that lists every field must add it. `is_partial` now reads that count rather than `outstanding_usd_nanos > 0`: a reservation of zero is still an outcome missing from the record, and an amount cannot answer a question about presence. No published total moves, since every rate card in this repository prices a call above zero.
- harness: `sharpebench_harness::checkpoint` gains the public `TreatmentAxis`, `ComparisonReceipt` and `ComparabilityRefusal` types. `SweepContract` already bound dataset, cost model, score configuration, runner, entrant and invocation, but binding alone never said which of the six an experiment varies on purpose, so "these two arms are comparable" was an assumption a reader could not check. `ComparisonReceipt::declare` states the axis, records the digests both arms carry on it, names every identity checked equal, and refuses naming the field that decided it: an off-axis identity difference, a different window matrix, seed list, failed-attempt budget or checkpoint schema, or an arm with no contract. Dataset, cost model and runner artifact are never declarable. Rotating a credential stays outside the bound identity, so it neither refuses a comparison nor invalidates a resume. Nothing in the scoring kernel changes and no existing call site moves; the addition is breaking only for code that matches these module paths exhaustively.
- sim: `sharpebench_sim::trajectory` gains the public `regrade_submission` function with `RegradeRequest`, `EvaluatorIdentity`, `RegradeReceipt`, `RegradeDisposition` and `RegradeRefusal`, all re-exported from the crate root. A failed evaluator can be rerun without buying another model trajectory, and the receipt is what links the original artifact, the evaluator identity on both sides including its wall-clock and memory limits, the inputs that changed, the reason and the superseding grade. A regrade invokes no agent: it consumes recorded decisions only, and an artifact that does not carry a decision for every step of its window is refused rather than replayed into holds the agent never made. A source listed as frozen published evidence yields an operational-only disposition, so the superseding grade can be reported but `into_published_replacement` refuses to let it stand in for the published record.
- core: two new public modules are exported from the crate root, so a glob import of `sharpebench_core::*` gains their names. `sharpebench_core::trial_census` adds `TrialRoster`, `CohortIdentity`, `TrialReport`, `TrialOutcome`, `CensusGate`, `AgentCensus`, `TrialCensus`, `CensusedScore`, `CensusError`, `census` and `attach_census`. `sharpebench_core::suite_controls` adds `ControlProperty`, `ControlObservation`, `ControlRun`, `ControlShortfall`, `ControlVerdict`, `SuiteControlEvidence`, `ControlError`, `evaluate_controls`, `bind_to_suite`, `ACCOUNTING_RESIDUAL_TOLERANCE` and `SUITE_CONTROL_INVENTORY`. Nothing existing changes shape: `CompositeScore` gains no field, the census is joined to a board beside it rather than inside it, and the committed golden score files and the two WASM golden files are byte-identical before and after. The 40 artifact digests in `paper/evidence/provenance.json` are unchanged.
- core: `sharpebench_core::suite_controls::ControlShortfall` gains the public variant `ComparatorReturnNotFinite { mean_return: f64 }`, so a `match` over that enum that lists every variant must add an arm. The economic comparator arm of `shortfalls_of` destructured `mean_return: _` and checked period counts alone, so a comparator reporting a NaN or an infinite mean over a complete series was published as `held: true` and counted into `all_held`. The sign and the size of the mean stay deliberately unconditioned, because an unprofitable comparator is a working apparatus running a policy that lost money, which is a fact about the market rather than a broken control, and the existing test pinning a mean of -0.004 as held is unchanged. Finiteness is a different question from sign: a negative or zero mean is a number the reader can compare a ranked entrant against, and a NaN or an infinity is the arithmetic reporting that it produced none, which establishes no comparable series at all. The protocol and accounting arm in the same file already refused a non-finite residual on that reasoning, so the file was internally inconsistent about it. No published number moves: the 40 artifact digests in `paper/evidence/provenance.json`, the committed golden score files and the two WASM golden files are byte-identical before and after, and no control in this repository reports a non-finite mean.
- core, harness: `sharpebench_core::suite_evidence` is a new public module exported from the crate root, adding `SuiteEvidence` and `suite_evidence`, so a glob import of `sharpebench_core::*` gains both names. `sharpebench_harness` gains the public `window_label`, `luck_floor_agent_id` and `trial_reports`. `SuiteEvidence` is the record a run publishes beside its board: the trial census against the roster the run declared, and the verdict on each of its controls, with `used_by_gate` recorded false on the record itself for the reason `SharpeDiagnostics` records it. The constructor is the only way to build one and routes the controls through `bind_to_suite` rather than `evaluate_controls`, so a producer cannot reach the evidence record while skipping the refusal of a control that is also a ranked entrant; a new producer inherits the check instead of having to remember it. `SuiteEvidence` is `Serialize` only: a deserializable `used_by_gate` would be a field an input document could set to true, and the whole purpose of the field is that it cannot be anything but false. The harness additions exist so a producer that declares its roster before the run reads the entrant ids and window ids the field will actually be assembled under, from one place rather than by formatting the same strings twice. No published number moves: `sharpebench run --json` and `sharpebench score --json` are byte-identical to the previous head on the committed field, the golden score files match byte for byte, and the 40 artifact digests in `paper/evidence/provenance.json` are unchanged.

### Changed
- edge, docs: three scope boundaries from Sharpe's own 1994 article are named, after an independent read of it against the kernel. The core survived the read unchanged: under the zero-rate cash convention `sharpe_ratio` is Sharpe's ex-post differential ratio exactly, `PassMode::RelativeToBenchmark` builds a true per-period differential against a risky benchmark, and no path lets a risky benchmark reach the scalar-subtraction form. (1) `HonestyConfig::sr_benchmark` is documented as the null value `SR0` in a test of `H0: SR <= SR0` rather than as a "benchmark Sharpe", the reading that invites the category error of entering an index's 0.5 and believing the verdict answers "do I beat the index". It does not: Sharpe's ratio against a risky benchmark divides by the standard deviation of the *differential*, so a fund at mu 0.08, sigma 0.20 against a benchmark at mu 0.06, sigma 0.15 correlated 0.9 has a differential ratio of 0.217 while the two standalone Sharpes are both 0.40 and their difference is 0. Even a riskless constant `c` enters as `SR - c / sigma`, not as a Sharpe to subtract. The field points at `PassMode::RelativeToBenchmark` for the differential test. (2) `docs/book/src/methodology.md` records that the ratio takes no account of correlations, so a rank is a choose-one-from-many verdict and not a marginal-addition one, `alpha_beta` against the field mean being attribution and not portfolio construction. (3) The same chapter records that every figure is ex post, and that an unadjusted historic ratio is not an unbiased prediction of an ex-ante one. Documentation only: no estimator, default, output or published number moves.
- stats, docs: the book no longer claims the manipulation-proof performance measure "cannot be raised by selling tail risk". What Goetzmann, Ingersoll, Spiegel and Welch license (property 2) is that an uninformed investor cannot *expect* to raise his *estimated* score, at a `rho` chosen so that holding the benchmark is optimal (their eq. 19), which this kernel does not solve for: it takes `rho` from the caller and defaults it to 3. On this repository's own two test streams the tail seller wins at every `rho` below about 1.6444 with the tail realized, `rho = 1` included, the geometric-average measure GISW themselves list as unmanipulable against dynamic manipulation; a tail that does not land in the sample is invisible at every `rho`, `Theta` being a sample average, scoring 0.01489 against the symmetric stream's 0.00428 at `rho = 3`; and raising the premium from 1.5% to 2.5% flips the ordering with the tail realized at `rho = 3`. The existing test was never wrong, asserting only `rho` in 2, 3, 4 with the tail realized; the sentence generalized past it. A new test in `crates/sharpebench-stats/tests/opt_in_diagnostics.rs` pins the bracket the ordering flips inside and both counterexamples. `manipulation_proof_performance` itself is unchanged and no published number moves.
- cli, docs: the importer's runtime notice names the exposure the integrity section identifies as the live one. `paper/sections/04-integrity.tex` records that what prevents option-based Sharpe manipulation for a harness-run agent is that the simulator executes linear target-weight orders only, and that an imported return series and a direct caller of `rank` have no such protection. Nothing on the import path acted on that: the notice at `crates/sharpebench-cli/src/import_cmd.rs` enumerated the absent audit trace, the absent calibration, the declared trials and the lower-bound reading, and said nothing about option-like or short-volatility payoffs, while its caveat test checked only those four words and so pinned the omission in place. An imported short-volatility series was therefore scored, ranked and handed to the operator under three caveats that do not apply to it and without the one that does. The notice and the embedded `_import_note` now say that payoff shape is unconstrained on this path, that large negative skew is not flagged, and that the manipulation-proof performance measure is the shipped statistic that speaks to shape, reachable as `sharpebench score <out.json> --diagnostics mppm`. The measure is described the way the book's [scope paragraph](docs/book/src/methodology-deflated-sharpe.md) now describes it, as a certainty equivalent at the risk aversion it is handed, which this kernel takes from the caller and defaults to 3 rather than solving Goetzmann, Ingersoll, Spiegel and Welch's eq. 19 against a benchmark, and which a sample average cannot compute over a tail that did not land in the sample. It is not described as a warrant that a series was not manipulated: on this repository's own streams a tail seller wins outright below a risk aversion of about 1.8, and in any sample where the tail has not yet landed it wins at every risk aversion, so the stronger sentence would be false. A second test pins the new wording and refuses the overclaiming phrasings. The measure is **not** run automatically on an import: `sharpebench import` writes a submissions file and computes no board, and the measure is defined over a board's pooled track, so running it there would mean the importer silently became a scorer. No number, gate, eligibility rule or rank changes.
- stats, core, docs, paper: the Sharpe statistics are worded against the standard-error convention they actually use, after an independent read of the five source papers. `probabilistic_sharpe_ratio` now records that its standard error is the plug-in one at the **observed** Sharpe (Lopez de Prado, Lipton and Zoonekynd 2026, eq. 3), not the one evaluated under the null at the benchmark (their eqs. 4 and 5, which ship as the opt-in `StandardErrorAt::Benchmark` diagnostic), and that changing it would be a methodology version bump rather than a fix. The claim that fat tails and negative skew lower the PSR is narrowed everywhere it appears (`docs/book/src/methodology-deflated-sharpe.md`, `paper/sections/03-benchmark.tex`): it follows from the skewness and kurtosis terms multiplying the observed Sharpe, and under eq. 5 the same terms multiply `SR_0` and vanish at `SR_0 = 0`, so "the PSR penalizes tail selling" is a statement about the evaluation point and not about the PSR. No estimator, default or output changes.
- core: `CompositeScore::field_reality_check_p` no longer documents White's Reality Check p-value as "the probability the leader's edge is luck". That is the posterior reading of a p-value the same statistic's Python binding already refuses in its own docstring; the field now states it as the probability, under the null that no agent beats the benchmark, that the leader would look at least this good given how many agents were tried.
- paper: `paper/src/essay-prose.md` no longer describes the PSR as "the probability that the true Sharpe exceeds a benchmark". The [literature audit](docs/audits/2026-09-09/LITERATURE-AUDIT.md) corrected that phrasing on the package surfaces in F1 and F17 and twice left the launch prose out of scope; it is the most widely read surface that carried it. Nothing numeric in the essay changes.
- stats: `per_period_from_annualized` states the assumption its callers depend on rather than only the algebra. Square-root-of-time scaling is exact for i.i.d. returns and, across periods, for log returns, which add; on dependent simple returns it ignores compounding and the factor is not `sqrt(periods_per_year)` at all (Lo 2002; Benhamou 2021, p. 3). `sharpebench_core::per_period_sr_std` and the paper already said so at their own conversion sites, and `BudgetPoint::oos_sharpe_annualized` now says it too, being a display figure scaled that way.
- stats: the manipulation-proof performance measure documents its input contract. Goetzmann, Ingersoll, Spiegel and Welch's `x` is an **excess** return over the per-period risk-free rate, so under this benchmark's zero-rate cash convention a portfolio return series is the right input and a caller whose cash earns a non-zero rate must subtract it first; passing an absolute return there scores a different quantity. `DEFAULT_MPPM_RISK_AVERSION` records that 3 is that paper's calibration choice and not a universal constant, and the docstring records that the paper's own introductory example does not reproduce (its stated excess returns give about 0.0154044 at rho = 2 and 0.0109728 at rho = 3, not the printed 1.036 and 1.109), so it is not usable as a fixture and is not pinned as one.
- edge, npm: the Harvey-Liu-Zhu gate's Fail sentence no longer reads a t-statistic as a posterior. It ended "likely a multiple-testing artifact", which states how probable a hypothesis is given the data; a `|t|` below the bar is a failure to clear the bar and supports no such statement. It now ends "the factor is not significant at that multiple-testing-adjusted bar", the register the deflated-Sharpe surfaces were corrected into. **Callers matching on the old text see a different string**: the field is `HlzGate::explanation`, reached as Rust `hlz.explanation`, Python `hlz["explanation"]`, npm `hlz.explanation` and the same key in the WASM and MCP payloads. The Pass sentence, the threshold, `passed`, `t_stat` and every number are unchanged, and no gate, score or rank reads the sentence. The literature audit recorded this string twice as out of scope, under F1 and F17 of the [literature audit](docs/audits/2026-09-09/LITERATURE-AUDIT.md).
- npm: `npm/pkg/sharpebench_bg.wasm` is rebuilt, because the sentence is compiled into it. The committed module was stale by three minor versions: it reported `sharpebench-stats/0.21.0`, so the working-tree `npm test` on the previous commit failed its methodology-version assertion before reaching anything else. CI and the release workflow both run `wasm-pack build` before testing or publishing, so no published package ever carried the stale module; only a working tree that trusted the committed copy did. The rebuild therefore moves the module from the 0.21.0 kernel to 0.24.0 as well as changing the sentence. `pkg/sharpebench.js`, `pkg/sharpebench.d.ts`, `pkg/sharpebench_bg.wasm.d.ts` and `pkg/package.json` are byte-identical to the committed copies. The module is rebuilt against the current tip rather than the tip it was first built at, because the binary embeds `panic::Location` records: rebasing over a docs-only change that added three lines to `crates/sharpebench-core/src/composite.rs` moved 22 bytes of line numbers in it, at the same total size. A committed build artifact therefore drifts from its source on changes that cannot alter behaviour, which is the same shape as the staleness above and the reason the release path builds it rather than trusting the checked-in copy.
- llm field: the rate card, the alias-expansion rule and the acceptance decision move to `paper/evidence/llm_pricing.py`, imported by both files that price a call. `examples/llm-agent/llm_agent.py` and `paper/evidence/assemble_llm_field.py` each carried a literal copy of the table and a restatement of the rule, recorded as a limit when the second was written: the rule was restated rather than imported because importing the shim would pull the Anthropic SDK into an assembler that reads only files, so two tables and two copies of one rule could be edited apart and a model could be priced by one side and refused by the other, or priced differently by each. They agreed at the time, checked before anything changed: the same three models at the same rates, the same eight-digit snapshot rule. The shared module imports nothing, so it carries nothing into either side; each file keeps its own refusal, `UnpricedModel` before the first observation in the shim and `SystemExit` in the assembler. Nothing about which models are priced, at what rates, or which served ids count as one of them has changed, so no computed cost moves. An operator adding a rate card now edits one file. See A8 in the [accounting review](docs/audits/2026-09-09/ACCOUNTING-REVIEW.md) and section 7e of [inherited repairs](docs/audits/2026-09-09/INHERITED-REPAIRS.md).

### Added
- cli, docs: `sharpebench rescore <bundle.json>` recomputes a submission's quality from a **declared submission bundle** instead of from whatever the operator points a path at. The bundle names, by content digest, every file the evaluator may read, and that manifest is the whole read set: the trajectory, the frozen dataset and the cost model are parsed from bytes that were hashed against their declared digests, and nothing else on the host is opened, so agent state sitting beside the bundle, a workspace, a cache, or a file the entrant wrote about its own profitability, is not an input and cannot move the recomputed score. A declared file whose bytes do not hash to its declared digest refuses with the role, the path, the declared digest and the digest on disk; a declared runner artifact that is not this verifier's binary refuses with both identities; a manifest path that is absolute or reaches above the bundle's own directory refuses before anything is read. An entrant's `claimed` figure is published beside the recomputation as `claim_matches_recomputation` and is never scored. The command composes the boundaries that already existed rather than restating them: `sharpebench_harness::verify_trajectory_strict` and `verify_trajectory_reexecuted` for the recompute, the arena's network-disabled hardened launch for `--reexecute`, and `crate::artifact_preflight` for the image and policy identity, the runtime allowlist, the functional probe and the verified cleanup, run against the bundle's own pinned image rather than against a flag. An absent `frozen_files` manifest is a refusal here and not a warning, by choice and not by discovery: a verifier whose scoring code is imported from a separate protected copy can warn about a missing manifest because its scorer is out of the entrant's reach regardless, and this command has no second copy. `--reexecute` offers deterministic policy re-execution and not recorded provider-response replay, so every report states under `not_established` that for an entrant whose decisions depend on a sampled model response a divergence is not evidence of tampering and agreement is not evidence that the recorded responses were the ones received. `--envelope` judges the declared compute budget: a difference in `cpu_millis`, `memory_bytes` or `wall_clock_seconds` refuses, because those bound what the agent could compute and two scores under different budgets answer different questions, while everything under `resources.disclosed` is environment description the envelope does not constrain and is published beside the score. No existing command, output or number changes.
- core: trial counts are taken from the declared roster instead of the rows that arrived. `trial_census::census` counts a suite against a `TrialRoster` declared before it ran, so `expected` is `entrants x windows x seeds` and never a row count, `completed` counts declared cells with exactly one completed report, `failed` carries the producer's reason per cell, and `unreported` counts declared cells no report covers. Every non-completion is named by a `CensusGate`. `run_identity::parse_keyed_field` already refuses a partial grid, but the grid it validates is the union of the keys that were submitted: a window that failed for every entrant and was never submitted leaves a complete product over the remaining windows, and nothing in the record then says the window existed. The property the module is built for is that a failed trial and a dropped trial are the same non-completion, so deleting the failed report moves one cell from `failed` to `unreported` and moves nothing else: `expected` is fixed by the roster, `completed` does not rise, the declared `CohortIdentity` does not change, and `AgentCensus::complete` stays false. `attach_census` publishes the counts beside each board row without touching `CompositeScore`, and a declared entrant whose every trial failed still appears, scoreless, with its counts and its gates, where a board built from the rows that exist would have dropped it.
- core: a control's identity, the property it was intended to establish and the outcome it observed are bound into one record, separate from the entrant rankings. `suite_controls::evaluate_controls` scores a cash or no-op control on whether the protocol round-tripped and the accounting identity closed, an invalid-order control on whether the refusal path refused every order it was given, and a buy-and-hold control on whether a comparable return series was produced. The comparator's mean return is reported and is deliberately not a condition: a working pipeline running a policy that lost money holds its control, and reading that as trading skill is the confusion the split exists to prevent. A shortfall is typed and names the component, so a broken accounting path fails its own control while the refusal control beside it still holds. A refusal control that was handed nothing to refuse does not pass vacuously, an observation of one property cannot be offered as evidence for another, and an empty battery is refused rather than reported as held. `ControlVerdict` carries no score field, and `bind_to_suite` refuses a suite in which a control identity also appears as a ranked entrant: a privileged row handed a perfect result because it is the apparatus is pipeline validation, not an attainable ceiling, and it must not be read off a competitive board as one. `SUITE_CONTROL_INVENTORY` binds identity, intent and outcome under the `run_provenance` digest, with the rendered `detail` line excluded and its reason stated.

- harness: a displaced journal-lock holder no longer removes the lock of the holder that displaced it. `Drop for JournalLock` removed whatever file was at its path, and `JournalLock::take_over` replaces that file while the incumbent is still alive holding a lock naming it, so the incumbent's ordinary exit unlocked the journal under the taker while the taker was live and spending, and any number of further gateways could then open it. Each lock document now carries the instance that wrote it and a holder removes only a file still carrying its own, so a displaced holder's drop is a no-op. `JournalLock::is_still_held` lets such a holder find out rather than discovering it by writing; nothing polls it, and what stops a displaced holder from spending is still the journal's compare-and-swap. The read and the unlink are not one operation, so a takeover landing between them can still lose the taker's lock. See A1 in the [accounting review](docs/audits/2026-09-09/ACCOUNTING-REVIEW.md).
- harness: an I/O fault by a journal's sole owner is no longer published as lost ownership. `GatewayJournal::save` decremented its version on any error, including a parent directory sync that failed after the rename had already moved the file to the new version; the gateway was then a version behind the file it owned, its next reservation was refused as a `Conflict`, and the sweep published `journal_ownership_lost: true` beside the pool for what was one owner's I/O fault. The landed case now keeps its version and reports `Unsynced`, and the reservation path latches `journal_unwritable`, which is what the file's state actually is: it holds a reservation this gateway will never settle. Money was safe before and is unchanged; the published diagnosis was wrong. See A7 in the [accounting review](docs/audits/2026-09-09/ACCOUNTING-REVIEW.md).
- harness: the gateway regressions are hermetic. They shared a system temp directory keyed on the process id, which the operating system recycles, and `ModelGateway::open` resumes any journal it finds, so a re-run could inherit a crashed run's spend record; one mutation run read 45 where it expected 15. Each test now takes its own directory, named with a counter and a nanosecond stamp as well as the pid and removed in a `Drop` that a panicking test still runs, so the test that leaks a lock deliberately leaks it where nothing else will look.
- harness: `a_takeover_is_explicit_and_records_who_it_displaced` asserted that a takeover records who it displaced by comparing the recorded pid against this process's own, which the taker writing its own pid satisfied just as well as reading the displaced document, and it did not assert the timestamp at all. It now writes the displaced holder's document with a pid and a timestamp this process cannot produce for itself, and asserts both.
- llm field: a malformed reply's cache record now carries the cost of the call that produced it, as the refusal and success records already did. It carried the token counts but no cost block, so replaying that decision reported a billed call as free. The replayed wire decision still carries none and cannot: it has to stay unparseable so the transport records an agent protocol fault, so the cost rides on the record, which is what the accounting reads. `paper/evidence/assemble_llm_field.py` prices malformed calls from the token counts on the record and is unchanged, so no published number moves.
- llm field: the call ceiling in `examples/llm-agent/llm_agent.py` now bounds provider requests rather than dispatches from the shim. One unit of `LLM_MAX_CALLS` was reserved before each `client.messages.create`, but the client was a bare `anthropic.Anthropic()`, so the SDK's default two automatic retries on 408, 409, 429, 5xx, connection faults and timeouts billed up to three requests against that one unit and a run could spend up to three times its declared ceiling. The client is now built with `max_retries=0`, so `LLM_MAX_CALLS=N` permits at most N HTTP requests to the provider for that model across every subprocess sharing the ledger, failures included. Nothing in the shim retries a transient failure: it spends its unit and fails the subprocess, and the harness respawn takes a fresh unit from the same ledger. The docstring's admission that one reservation could cover several billable requests is gone because it is no longer true. Because the shim imports whatever SDK the operator installed, and a later major version could accept `max_retries` and stop honouring it, `assert_no_provider_retries` reads the effective setting back off the constructed client before the run starts and refuses to start if it is not zero or cannot be read: for a money ceiling, not starting beats overspending. The guarantee is therefore conditional on that check rather than on an SDK version. A new `llm-shim` CI job runs the shim's ceiling and model-identity regressions, which no workflow ran before, against a pinned `anthropic==0.112.0`, the version the retry reading and the load-bearing test were established on; anthropic 1.x is a different SDK (it depends on httpx2) and its retry semantics are not assumed from the 0.x source. See [inherited repairs](docs/audits/2026-09-09/INHERITED-REPAIRS.md#4-the-ceiling-counted-dispatches-not-provider-requests).
- harness: a gateway that spends a money journal now owns its path exclusively. `ModelGateway::open` and `run_gateway_sweep` take a lock file, `<journal>.lock`, created with `create_new` so the file system picks one winner, and hold it until the gateway drops. The journal's compare-and-swap was a check-then-act race: two writers could each read version N, each pass the check, and the second rename could erase the first's records or let both spend one allowance. A second gateway is now refused when it opens, as an `io::Error` of kind `AlreadyExists` carrying a typed `JournalLockError::Held` naming the lock file. A lock left by a crashed process is refused too, never broken automatically; clearing it is `JournalLock::take_over(path, reason)`, which records the displaced pid and the stated reason inside the lock that replaces it. Reading takes no lock, so `sharpebench gateway` still reports on a sweep in flight and says whether the path is owned, in a new `journal_lock_held` field. The version check stays, as a second line of defence for a journal that moved under a single writer. Two hosts sharing one journal path over a network file system are still not separated: `create_new` is only as exclusive as the remote server makes it.
- harness: a gateway settlement that cannot be written now stops the gateway instead of being dropped. `settle_and_persist` latched only on `JournalSaveError::Conflict` and ignored `JournalSaveError::Io`, on the ground that a lost write can only over-report spend. That holds only while observed usage stays at or under its reservation, and this gateway records usage above a reservation, so a restart read the smaller reservation and under-reported real spend. Both failure modes now latch: the answer whose settlement did not land is refused rather than returned, every later request is refused as `journal_unwritable` or `journal_ownership_lost` before anything is dispatched, and `HostObservedUsage` gains a `journal_unwritable` field beside `journal_ownership_lost`. Rust code that constructs `HostObservedUsage` with every field listed must add it; the JSON on an entrant's board gains the key.
- release: the registry check polls crates.io and npm for up to ten minutes per package instead of checking crates.io once and npm for 100 seconds. v0.20.0, v0.21.0 and v0.22.0 each failed that check on registry lag alone and passed on a rerun.

Waits are recorded on the failed attempt they follow and totalled as `attempts.backoff_ns_total`, never inside an attempt's duration, and the schedule is bound into the checkpoint identity with `BackoffSchedule::bind_invocation`. - cli: `verify-trajectory <traj.json> --reexecute [--cmd "<prog>" | --http <addr>]` runs `verify_trajectory_reexecuted`: the strict checks, then every captured run re-executed with a fresh agent (the named external entrant, or the reference agent the trajectory names). The first divergent score-bearing decision exits 1 with `reexecution_diverged` and the typed divergence; a transport, protocol or spawn failure during re-execution exits 1 as `reexecution_transport_failure` rather than being read as non-determinism. Contradictory or unlaunchable requests exit 2. Plain `verify-trajectory` output is unchanged.
- harness: `run_resumable_sweep_with_backoff`, the checkpoint driver under a backoff schedule (the wait is saved on the failed attempt before the driver sleeps, retries are numbered within the cell's round), and `run_agent_resilient_faulted`, the unpersisted resilient sweep returning its attempt ledger with fault evidence. `run_resumable_sweep_faulted` and `run_agent_resilient_with_backoff` delegate to them unchanged.
- External `run --rate-card <json>` quotes reported token usage under frozen provider/model/revision and integer USD nanodollar rates. The card is checkpoint-bound, failed-attempt usage survives recovery, missing or overflowing accounting is unavailable, and quotes remain separate from the legacy cost columns and ranking. No live prices or provider-verified billing are claimed.
- Checkpointed external sweeps support `--retry-runtime-failures`. Recovery preserves the execution contract and all recorded attempts, never reruns completed or agent-fault cells, and allows at most three extra rounds per cell. Per-round budgets survive interruption; observed attempts are persisted before another attempt starts. This does not recover an old binary's checkpoint under a changed binary or prove that every transport error was caused by infrastructure.
- External-agent `run --json` rows and incomplete-sweep errors include rank-neutral attempt counts and observed duration. The board remains an array, reference rows and scoring are unchanged, and unobserved monetary usage is explicitly unavailable rather than zero.

  cross-environment cells, while exhausted infrastructure failures suppress the

- core: composite scores report the support behind calibration, crowdedness,

  `field_crowdedness_peers`, and `rolling_windows`.

### Changed
- sim: a subprocess agent that dies during the decide wait is reported immediately as the new retryable `DecideError::Exited` carrying its exit status, instead of burning the full 30s decide budget and reporting `Timeout`: a container or process that crashes at startup was misclassified as a slow one. ### Changed
- cli: `run --cmd` now prints an unsandboxed-execution warning to stderr on every run, in both text and `--json` mode. What changed is that the choice is now recorded instead of implicit, so an unsandboxed run cannot be mistaken for a sandboxed one after the fact.
- sim: the stdio transport caps one decision line at 8 MiB, the same budget the HTTP transport already applied to a response, and reports a line past it as the new non-retryable `DecideError::Oversized`. The reader was doing an unbounded `read_line` on untrusted subprocess output, so an entrant that writes without ever sending a newline grew the buffer until the harness died, losing every other agent's results in the same sweep. - paper: `make-provenance.py` refuses a scope pattern that matches no file, and `check-provenance.py` fails a manifest that records one.
