\section{Mechanism that affects no reported result}\label{app:mechanism}

This appendix describes engineering contracts and capabilities that protect future fields or serve operators and that change no number in \cref{sec:experiments}. The descriptions were checked against the source tree after the 0.27.0 release, including the repairs merged since that release. None was exercised by the frozen v0.9.0 evidence, and none is a result.

\subsection{A resumable sweep is bound to its complete execution geometry}\label{app:sweep}

The checkpoint's \texttt{SweepContract} records a schema version; SHA-256 identities for the dataset, cost model, score configuration, runner executable, entrant artifact and invocation, where the invocation identity folds in the effective non-secret environment and any fault plan, retry-backoff schedule or token rate card the sweep runs under; the exact ordered windows and seeds; and the retry budget. The bound resume path requires equality over the whole record, including caller-supplied seeds and retry budget, and over the window-major task matrix. The observed path takes seeds and the retry budget from the contract itself, so it compares schema, digest shape and the window matrix and says so, rather than comparing those fields against themselves. A checkpoint for the same agent and matrix but different prices, costs, scorer, executable, entrant, invocation or retry policy is refused rather than mixed with new runs. Building a contract whose windows overlap or are listed out of time order is refused, and every bound sweep runner refuses such a contract before it reads or writes a checkpoint (\cref{sec:stats}). The command-line path requires an explicit lowercase SHA-256 entrant identity for HTTP or host-command entrants and derives the identity of a digest-pinned image automatically. Runtime and agent failures remain distinct after retries: an exhausted harness or infrastructure failure produces no run and makes the sweep incomplete, so the command emits neither a score nor a board; an agent protocol or resource fault produces a full-length failing sentinel for that cell and counts against $\passk$. An incomplete sweep is recoverable only under an explicit request: \texttt{--retry-runtime-failures} requeues runtime-failed cells under the same contract, grants at most three additional rounds per cell over a checkpoint's lifetime, and never touches a completed cell or an agent-fault cell. Per-round attempt budgets are persisted and attempts are appended rather than rewritten, so an interrupted round cannot be resumed as an unspent one, and the checkpoint schema version was raised to reject a checkpoint written before those budgets existed rather than read its missing spend as zero.

Binding alone never says which identity an experiment varies on purpose. \texttt{sharpebench compare} reads the two checkpoints two sweep arms already wrote, declares the one axis the operator names as the treatment (entrant, invocation or score configuration), names every other identity it checked equal, and refuses a comparison with the field that decided the refusal; dataset, cost model and runner artifact cannot be declared as the axis, so the difference that would void a comparison cannot be declared away. The receipt is marked as unused by the gate and never reaches a score.

Every external sweep also publishes a rank-neutral attempt summary, on the entrant's board row when the sweep succeeds and on the error when it does not; it enters neither the score nor the $\passk$ denominator. The same row discloses the isolation its transport gives between cells. A digest-pinned image runs each (window, seed) cell in a fresh container; a host command runs unsandboxed, so files it writes can reach the next cell; and an HTTP endpoint is started and stopped by the operator, not the harness. Seed replicates of a window are therefore independent by construction only under the first. The class is derived from the transport, never from anything the agent sends, and the checkpoint's entrant and invocation identities carry it, so a sweep cannot resume under a different class. It is a disclosure and detects no carried state, and no score or rank reads it. A missing or unmeasured cost in that summary is reported as unavailable rather than as zero. Two priced records may appear beside it and neither is a rank input: a frozen integer rate card quotes what an entrant reported it used, and the host-observed gateway (\cref{app:capabilities}) records what the host itself saw a provider report, priced once against the same frozen card. Reasoning tokens are a subset of output tokens under both. Entrant-reported usage is a self-report and host-observed usage is an observation of a provider's own report; neither is verified billing, and this mechanism does not establish which model an entrant called.

\subsection{The process gate and the ordering of a lifecycle}\label{sec:lifecycle}

The process gate as described in \cref{sec:stats} counts events. That is enough to catch an order whose risk-gate flag is false, and not enough to express the control that matters, which is that the risk evaluation happened \emph{before} the order it authorizes. Counting cannot separate those two claims, so we added an ordering check to it.

Ordering alone is still not the control. An ordering check that ignores what each step concerns is satisfiable by an agent that never emits an out-of-order event: it evaluates risk on one instrument, then submits on another, and every transition is in sequence. We found the hole by reading a system that had ordering without that linkage, and closed it by making the subject part of the transition. A typed lifecycle runs observation, decision, risk evaluation, submission, acknowledgment, fill, reconciliation. Every transition carries the subject it concerns, an instrument by symbol id or an open position by position id, held as distinct kinds so that authorizing work on a position does not authorize a fresh instrument-level order or the reverse. A submission for subject $S$ is legal only when a risk evaluation for the same $S$ passed earlier in the trace; a failing evaluation revokes any standing authorization for that subject, so the most recent verdict is the one in force. Subject equality is an identifier comparison over opaque ids supplied by the harness, and no substring of them is ever interpreted.

Seven ordering failures are block severity, because each one lets capital move without the control that was meant to gate it:
\begin{enumerate}[leftmargin=*,itemsep=1pt]
\item a submission with no passing evaluation for its own subject;
\item a subject that drifts between two transitions of one order;
\item an acknowledgment for an order never submitted;
\item a fill never acknowledged;
\item a reconciliation against an order that never filled;
\item a blind retry of a write whose outcome was never observed;
\item any other backwards or skipping transition.
\end{enumerate}
Five are warn severity, because the control ran and the record is incomplete: a stage recorded twice in a row, a fill left unreconciled at the end of the trace, a submission with no recorded decision, a decision on a subject never observed, and a resubmission whose predecessor has no recorded outcome at all.

The blind-retry case is worth stating separately, because it is where a pure kernel could easily have guessed. If a submission's acknowledgment never arrives, the venue may or may not have committed it, and a retry that carries no stable client-side key is a second live order rather than the same intent sent twice. The kernel reads no clock, so silence of any duration is not evidence available to it: ambiguity is a fact the trace states, through a typed unobserved-acknowledgment transition the harness records, and the only positional quantity the check uses is the index of a submission within the recorded sequence. A retry that shares the earlier attempt's client key joins the same intent and is clean; a retry with an absent or different key is the block-severity failure, where an absent key matches nothing, including another absent key. A shared key makes a retry safe without resolving the ambiguity, so the check tracks the ambiguity per intent across the whole retry chain and only an acknowledgment, fill or reconciliation observed for any member closes it: a keyless submission for the same subject while such an intent is open is a blind retry however many keyed retries preceded it. When the trace records no outcome for the outstanding write at all, the check reports a separate warn-severity unavailability rather than asserting a verdict in either direction. No trace committed anywhere carries the new transition, so no published board moves. The unauthorized-submission report carries the subjects that \emph{were} authorized at that point, which is what distinguishes ``no risk evaluation ran'' from ``a risk evaluation ran, on something else''; the second is the case a subject-blind check waves through.

Two properties of this check are deliberate and bound what it proves. It is typed over the same event representation the trace already uses, and nothing in it inspects a tool name or matches a substring: tool names are scaffold-specific, so matching them would score naming conventions rather than behavior. And it is additive. The host scoring path is unchanged: ranking still computes the counting score, and the ordering report is produced by a separate entry point that a caller composes with it, folding block and warn counts into the same severity arithmetic. An opt-in, versioned rank mode, \texttt{lifecycle-certified/v1}, adds a certification verdict beside every row, certified only when the row is host-eligible, every run carries lifecycle evidence and no run has a block-severity ordering violation, and leaves the host board unchanged. So ordering is available to a caller and is not a conjunct of \cref{eq:eligible}, and no result in \cref{sec:experiments} is affected by it. It is exercised by unit tests, including the case that a passing evaluation on one instrument does not authorize an order on another, and by no submitted run: the field prevalence of ordering violations is unknown for the same reason the process gate's is (\cref{sec:limitations}).

\subsection{Seven additional reference-signal primitives}\label{sec:entrants}

The largest objection to every result in \cref{sec:experiments} is that the field is the author's (\cref{sec:limitations}). \Cref{sec:external} answers part of it by scoring four rules whose specifications come from the published literature, and the kernel also ships seven further signal primitives in the same spirit, so that a reader has specified opponents to check line by line rather than an author's discretion to take on trust:
\begin{enumerate}[leftmargin=*,itemsep=1pt]
\item a regime-modulated reading of Wilder's RSI, which flips which extreme it fades according to a coarse three-bucket trend context \citep{wilder1978new};
\item a bounce counter that fires only on a re-entry into an extreme zone rather than on a first touch;
\item a signal gate that separates what to trade from when by requiring a moving-average crossover to confirm an oscillator \citep{brock1992simple};
\item a time stop that caps how long an entry may sit unresolved, which is the failure a price stop never sees \citep{kaufman2013systems};
\item an ATR breakout whose trigger distance scales with the market's own noise, filtered on range expansion \citep{wilder1978new};
\item O'Neil's distribution-day count \citep{oneil2009howto};
\item O'Neil's follow-through day \citep{oneil2009howto}.
\end{enumerate}

Four house rules are what make them scoreable rather than merely present. Every stateful primitive takes its previous state by value and returns the next one, so there is no hidden state, no interior mutability and no clock, and replaying the same inputs from the same starting state is deterministic by construction. Every threshold is supplied by the caller; a primitive never fits a parameter to the data it is fed, and each published default is named as a starting point rather than as a value discovered here. Indicator inputs arrive as numbers already computed, so an entrant can be wired onto any bar source without this module owning an indicator library. And nothing does input, output or randomness. They are entrants, not infrastructure: no part of the scoring kernel calls them, and they exist to be scored by it through the same gates as everything else.

No field evaluation has been run on any of the seven. They are specified and unit tested, and that is the entire claim; no number anywhere in this paper is produced by them, and \cref{sec:external} remains the paper's only externally specified field.

\subsection{Agreement and dissent, measured without a judge}\label{sec:agreement}

Two questions the kernel could not previously ask are now answerable from the same judge-free discipline as the gates. Both are textbook estimators over numbers, with no model anywhere in them, which is the reason they belong in this kernel rather than beside it: a reader who meets the words \emph{agreement} and \emph{dissent} in an agent-evaluation paper should expect a language model to be grading something, and here nothing is.

\emph{Does the automated gate agree with the person who triaged the gold set?} Raw hit rate does not answer it. Two independent decision rules that each approve 95 percent of entries agree on about 90 percent of them by arithmetic alone, having learned nothing about one another. Cohen's kappa \citep{cohen1960kappa} subtracts the agreement two raters reach by guessing at their own observed marginal rates, so a gate that approves everything scores near zero however high its hit rate; Spearman's rho \citep{spearman1904proof} compares the ordering of the continuous severities behind the two decisions, which survives a disagreement that is only about where the threshold sits. Ties take the midrank convention \citep{kendall1948methods}. The binarizer that makes a continuous gate output comparable with a yes/no triage takes its threshold from the caller and never infers one from the data, so the operating point is an input to the measurement rather than something the measurement fits.

\emph{When a rerun moves the numbers, did the ranking move or only the levels?} The two call for opposite responses. If the ranking moved, the board is not reproducible and cannot be published as a ranking at all until the instability is found. If every entrant shifted together, the order is safe to publish and the absolute figures must carry the arm that produced them. The split is measured from one pair of score vectors: rank movement as $(1-\tau_b)/2$ using Kendall's tau-b \citep{kendall1938rank}, whose tie correction \citep{kendall1945ties} appears in both denominators so tied scores neither inflate nor deflate the reading, and level movement as the mean absolute difference between arms over the pooled range of every score in play, which needs no distributional assumption and is bounded in $[0,1]$ by construction, since every value lies inside the range it is divided by; the implementation still applies a clamp, which the construction makes redundant. A degenerate arm returns no reading rather than a flattering one: an arm with every value tied leaves no ordering to compare, and a pooled range of zero is agreement by degeneracy rather than a measurement. The verdict that a set of arms is safe to gate on, safe to publish as a ranking only, or not safe to gate on at all is read off two operator-supplied ceilings, which default to $0.05$ on rank movement (equivalently $\tau_b \ge 0.90$) and $0.10$ on level movement. Those defaults are operating requirements chosen by the operator, not constants measured from anything.

Nothing here knows what an arm is, so the machinery generalizes off judges entirely: execution seeds, evaluation windows, cost profiles and whole scorer configurations are the same shape of input, and \cref{tab:costsens} is exactly the kind of multi-arm comparison it is meant to summarize. We report the modules as built and tested, and no dissent or agreement figure over the committed evidence is claimed in this paper: the gold-set triage that would supply kappa's second rater does not yet exist at a size worth reporting, and the arm comparisons in \cref{sec:experiments} are stated as the raw per-arm numbers they have always been.

\subsection{Other capabilities of the current release}\label{app:capabilities}

\paragraph{Special functions.} The special functions behind PSR and the deflation bar were measured against a 60-digit reference and the substitution was then rejected, which is a disposition rather than a deferral. A \texttt{statrs} implementation is closer to the reference on almost every argument the kernel evaluates, improving the worst absolute error by three to seven orders of magnitude, and neither implementation is correctly rounded. It is rejected on a property the accuracy work did not measure: the two code goldens regenerated under it reproduce on the platform that produced them and fail on the other two supported targets, while the shipped bodies pass on all three. A disclosed and bounded error identical everywhere is compatible with a benchmark that promises byte-identical rescoring; a smaller error that varies by target is not, because it makes two honest operators disagree about the same submission. The shipped error sits orders of magnitude below every bar the kernel tests against, so nothing reported here turns on it, and the exact returned bits are pinned in a test so a silent change fails before it reaches a golden fixture.

\paragraph{Opt-in return diagnostics.} \texttt{sharpebench score --diagnostics} reports, beside an unchanged board, a PSR with the first-order autocorrelation term of \citet{lopezdeprado2026howto}, a PSR whose standard error is evaluated under the null, the manipulation-proof performance measure of \citet{goetzmann2007manipulation} at a caller-supplied risk aversion, and the expected shortfall of the pooled track. The shortfall is the mean of the worst 5 percent of returns, with the observation that straddles the tail boundary entering at its fractional weight, and it is reported with the tail size, the number of losing bars and their share of the track. It is withheld, with the reason, when the tail holds fewer than ten whole observations. It separates tracks that downside deviation cannot: a track that loses $0.02$ on half its bars and one that loses $0.04$ on one bar in eight have the same downside deviation. Like the manipulation-proof measure, it sees only losses that have occurred. The gate, eligibility and the rank read none of these diagnostics, and no table in this paper reports them.

\paragraph{Volatility-response sizing.} The \texttt{sizing-response} diagnostic of \texttt{sharpebench verify-trajectory} replays a captured trajectory through the engine and pairs, on every bar that has a full volatility window, the book's gross exposure after that bar's fills, as a fraction of the net asset value before them, with the trailing realized volatility averaged across symbols (by default the sample standard deviation of the 20 simple returns ending at that bar, so no later close enters). It reports Spearman's rank correlation between the two, the median exposure in each volatility quintile and the pair counts. Constant exposure, constant volatility and fewer than 30 pairs are reported as typed unavailability rather than as a number, so buy-and-hold reads as constant exposure and not as a correlation of zero. The diagnostic tests no significance, because pairs from different execution seeds share bars, and it reads volatility at the level of the whole book. A six-month production record of LLM trading agents found a median leverage of 5.0 in every volatility sextile across a 5.7-fold volatility spread, with a Spearman correlation of $-0.001$ between volatility and leverage \citep[p.~7]{barton2026production}; this diagnostic measures the same relation for a SharpeBench run. No gate, eligibility rule or rank reads it.

\paragraph{Timing-luck floor.} A board's reference agents decide on every bar, so no row has a decision schedule whose phase could be moved. \texttt{sharpebench timing-luck} gives every row a schedule. At a declared cadence $m$ each row rebalances every $m$ bars, and the report runs each of the $m$ phases of that schedule over the full declared windows, so every phase reads the same bars and the phases differ only in the dates on which a row acts. The rows are the reference field \texttt{run} ranks when no entrant is named, namely buy-and-hold, momentum and three luck-floor agents, together with the hold control, which never trades and therefore reports no figure. At each phase the report takes the seed-averaged pooled track that the board's own PSR and deflated Sharpe read, gives that track's Sharpe ratio and its deflated Sharpe, and summarizes each figure over the measured phases by its minimum, maximum, range and standard deviation. The report holds the deflation bar at the inputs each row's score records at phase 0, because a board deflates an entrant against one field and moving that entrant's schedule does not move the field; the dispersion each phase's own field measured is listed beside the figures. A six-month production record of LLM trading agents reports identical contracts at a $\pm 15$-minute schedule offset returning $-88$ against $+21$, $+17$ against $-38$ and $+9$ against $-75$ dollars, and asks an evaluation to know the floor that the schedule alone sets \citep[p.~15]{barton2026production}. The command runs no entrant and calls no model, so the floor it measures belongs to the protocol and the dataset rather than to any submission. Nothing but the schedule phase varies, since the execution seeds, the cost model and the roster are the same at every phase, so a reported range is the whole effect of the phase at that cadence on that data rather than a confidence interval. It does not replay recorded decisions late, and it does not match an entrant's exposure against random timing; the two replay reports below do both, over a captured entrant rather than over the reference field. The document is \texttt{sharpebench.timing-luck.v2}, it carries \texttt{rank\_input: false}, and no gate, eligibility rule or rank reads it.

\paragraph{Decision stability.} $\passk$ across execution seeds asks whether an outcome repeats and not whether an agent's choices repeat, so an agent that samples a different order each time it is asked can pass it, and on the board it is indistinguishable from one whose decisions are a fixed function of what it saw. A paired replay of 416 captured production scenarios placed three frontier models between $263.27$ and $264.37$ basis points of regret, with every interval overlapping every other and every Holm-adjusted test against the leader non-significant, while in a forced-action arm of the same league repeating one scenario three times changed the chosen symbol and side in 35 percent of cells for one model against roughly 90 to 95 percent for the other two; the same record also notes that more than one action can satisfy a qualitative strategy's intent, so a changed choice is not automatically a wrong one \citep[p.~12]{barton2026production}. An advisor audit reports validity, stability across repeated runs and agreement with a deterministic baseline as three axes that a single number conflates, and measures stability as the mean pairwise overlap of repeated recommendations, with an amount-aware term when a scenario requires dollar sizes \citep[pp.~3--4]{barbieri2026auditing}. \texttt{sharpebench decision-stability} measures the same axis over captured SharpeBench trajectories. Every captured run of a window is a replicate, and the command regenerates each step's observation by replaying the recorded decisions through the engine, then identifies it by a digest over the canonical form the forecast contract digests use. At each step it splits the replicates of a window by observation digest, compares the decisions inside each part, and splits again by the decision made, so a compared group holds the replicates that were shown equal observations at that step and at every earlier one, and that also decided alike at every earlier step. An agent that honors the determinism contract therefore reports exactly zero. Two decisions differ when their order arrays have different lengths, or when the orders at one position differ in symbol, action, target weight or confidence, compared exactly and without a tolerance, while reasoning text, per-order rationale and reported cost are ignored. The headline figure is pairwise. A compared group of $n$ replicates holds $n(n-1)/2$ pairs, and the rate is the differing pairs over the pairs, summed over the compared groups. The pairwise form is chosen because the share of groups that differ grows with group size at a fixed per-replicate flip probability, so it would move with how many captures a caller supplies. For a binary choice with flip probability $q$ a group of $n$ differs with probability $1 - (1-q)^n - q^n$, which at $q = 0.25$ climbs from $0.375$ at $n = 2$ to $0.822$ at $n = 6$, while under the same independent choices over options of probability $p_j$ a pair differs with probability $1 - \sum_j p_j^2$ at every group size. The report gives the distribution of group sizes beside the rate as context and never divides it into the rate. It types the rate unavailable rather than reporting a zero when no window holds two replicates, and when replicates exist but no step's history was shared by two of them. A copy of a capture agrees with its original by construction, so the command refuses an input named twice, reports the runs of one window whose serialized bytes are equal, and refuses the field unless the caller declares those runs separate executions; equal bytes cannot distinguish a repeated capture of a deterministic agent from a copy, so a zero over declared identical replicates is only as good as that declaration. The rate carries no interval, because a bootstrap over replicate runs would draw the same run more than once and a run always agrees with its own copy. A zero rate says nothing about the steps that left the comparison, and the rate measures consistency rather than quality, since a stable agent can be wrong every time. The document is \texttt{sharpebench.decision-stability.v1}, it carries \texttt{rank\_input: false}, and no gate, score or rank reads it.

\paragraph{Exposure-matched random timing.} An entrant that sits flat through most of a window and is long through a rising stretch of it can clear the luck floor, which is fully invested, and the significance gate, which tests mean return above cash, without either one asking whether its timing beat random timing at its own exposure. \texttt{sharpebench verify-trajectory --timing-null} asks that question of a strictly verified capture. It steps each run's recorded decisions through the engine, calls a bar invested when gross exposure after that bar's trades exceeds $10^{-9}$ of net asset value, and takes the run's holding periods to be its maximal stretches of invested bars. Every draw keeps each period whole, with the entrant's own decisions for its bars, and places the periods elsewhere in the same window by shuffling their order and spreading the flat bars over the gaps as a uniformly random composition, so the number of periods, their lengths and the gross exposure inside them are the entrant's and only the dates on which they fall move. Each draw is replayed under the run's own window, execution seed and cost model, and the run's own per-period Sharpe ratio is reported as a mid-rank percentile among the draws.

The percentile is only as good as the way the draws are formed. Placements are drawn from a stream keyed by the seed and the window, so every execution-seed copy of a window places its periods on the same bars; before that repair, independent placements per copy shrank the spread of the reference mean and put $30.7$ percent of no-skill entrants with eight copies above the $95$th percentile. Each percentile is reported with its Monte Carlo standard error, about $0.035$ near the middle at the default of 200 draws, beside the number of distinct placements the run admits, so a reader can see when a run's draws are repeating rather than sampling. A cost model with execution noise or a finite liquidity cap is refused rather than reported, because there whether an order fills depends on when and how often orders are sent, so a moved holding period no longer carries the entrant's exposure; under the realistic profile a review measurement over 400 runs found the draws holding about 126 bars per run against the entrant's 147 and a no-skill entrant's mean percentile at $0.40$ rather than $0.50$ on a driftless panel. A run with no timing to test, never invested or always invested, is typed unavailable rather than given a degenerate percentile.

\paragraph{Lagged replay.} \texttt{sharpebench verify-trajectory --lagged-replay} replays every run of a capture with each recorded decision executed a declared number of bars late and reports the mean per-run Sharpe ratio and the pooled mean per-period return beside the undelayed figures. The stressed profile's declared two-bar decision delay is measured this way, by calling the library function with that profile's cost model and a lag of two, which leaves the profile and the meaning of every record produced under it unchanged (\cref{app:simdata}); the command-line flag replays under the cost model the capture is bound to, which for command-line captures is the typical profile. Within a run every row, the undelayed one included, is computed on the bars after the latest bar at which any row first holds a position, so no row carries its opening trade and every compared bar is earned by a position the row already held; each run reports how many leading bars it skipped and how many it compared. A run whose rows cannot all be compared is typed unavailable and left out of the aggregate rather than entering it as a Sharpe ratio of zero, which is what a flat book would otherwise contribute. The window's end is not symmetric, and every report carries the asymmetry: a lagged row never executes the run's last few recorded decisions, whose fills would land beyond the window, while the undelayed row executes them on the window's final bars.

Both reports compare an entrant's decisions with the same decisions at other times, and that comparison is fair only where the entrant's own orders do not move the prices its positions are marked at. Every report carries the condition. SharpeBench marks every position at the frozen dataset close and charges own-order impact on the fill price of the trade that causes it rather than on a later close, so the condition holds under all four shipped cost profiles and a test checks it to within $10^{-12}$; a market model in which an entrant's orders move later prices, such as a shared order book, would void both. Both also replay decisions rather than the policy, so an agent that would have decided differently at another time is not re-run, and the timing reference keeps the entrant's cross-sectional choices inside each period, so it tests when the entrant was invested and not what it held. Neither report enters a gate, an eligibility rule or a rank, and neither has been run over the frozen field; the figures above are calibration measurements of the diagnostics themselves, and no result in \cref{sec:experiments} comes from either.

\paragraph{Image preflight.} The image preflight of \cref{sec:integrity} is opt in and raw-byte scoped, and a negative result is not an absence-of-memorization result. An optional runtime allowlist admits an image only when its container export holds the listed paths and nothing else, apart from the entries Docker's init layer adds in exactly the shape Docker gives them, and a functional probe then runs before the entrant is admitted.

\paragraph{Host-observed model gateway.} The gateway answers an entrant's model calls over the entrant's own standard input and output between an observation and its decision, so a network-disabled entrant is evaluable through the host, with host-owned credentials, bounded envelopes, a reservation taken and persisted before each dispatch and an append-only money journal. A gateway owns its journal exclusively through a lock created atomically, keyed on an identity carried inside the journal document, and refuses a second holder; a stale lock is refused rather than broken. A settlement that cannot be written stops the gateway before it reserves or dispatches again, and reopening a journal that holds a reservation with no settlement beside it is refused rather than resumed, because such a journal understates spend. The journal and the usage record also count the parsed provider answers by stop reason, so an answer the output ceiling cut off is not reported as a clean completion: an entrant can parse a truncated answer into a decision or read it as an abstention. The counts are rank-neutral. A journal that holds any stop reason is written under schema \texttt{sharpebench.gateway-journal.v2}, which a binary built before the class existed refuses rather than rewriting the journal without the field. No networked transport ships in the repository and the operator supplies one; what the host observes is a provider's own usage report rather than a verified invoice; two hosts sharing one journal over a network file system are not separated; and no gateway has served a real provider.

\paragraph{Receipts for rescoring and regrading.} \texttt{sharpebench rescore} and \texttt{sharpebench regrade} are described with the replay path in \cref{sec:attest}. Neither adds a second path from which a score is published, and a regrade of frozen published evidence is operational only.

\paragraph{Trial census and suite controls.} \texttt{sharpebench run} declares its trial roster, the product of the entrants, windows and seeds it will field, before the first agent runs, and publishes beside the board a census that counts completed, failed and unreported cells against that roster, so a failed trial and a dropped one are the same non-completion. It also publishes verdicts for two controls over the same dataset, windows and seeds: a no-op policy whose net asset value must return exactly to its opening value, and a refusal control whose invalid orders must all be refused by the same decision validation live entrants face. Each control's identity, intended property and observed outcome are bound under a digest the release computes and publishes beside what that digest covers. A control that is also a ranked entrant is refused, none of this reaches the gate, eligibility or the rank, and the frozen evidence predates all of it.

\paragraph{Fault injection and faulted windows.} External sweeps accept a seeded fault plan and a retry-backoff schedule, both bound into the checkpoint's invocation identity, and trajectories of external entrants can be captured and re-executed through the same transports; a window opened under a fault plan binds its digest (\cref{sec:attest}). No fault plan was applied to any evidence reported here.

\paragraph{Memory activation receipts and scenario transitions.} The memory-ablation crate separates claims a memory ablation used to run together. A treatment-activation receipt counts a retrieval arm as activated only where the offered memory bytes match a whole decision-boundary input segment made available no later than the decision, so memory that was written but never exposed does not count, and a placebo arm of matched byte length is compared with the retrieval arm only under identical model, ordered task and budget identities. An agent that cannot produce receipts is reported as unavailable with its lift labeled a proxy, and every report states that causal trading improvement is not established. Scenario-transition manifests declare fresh-episode or continuous-portfolio carryover explicitly, refuse an undeclared mode, and build each stage's observation only from facts dated no later than that stage's effective date, so a later stage's fact cannot change an earlier observation and an earlier stage's failure stays on its own row. Neither has been run on any agent, and this paper reports no memory result.

\paragraph{The Lean model.} The Lean project of \cref{sec:forecast-quality} proves only its declared scope. No test references a Lean declaration, so Rust tests of the same properties are topical coverage evidence rather than formal verification of the Rust code, and its rank-projection theorem holds by definition for any pair of types.

None of these mechanisms is claimed to be first of its kind or universally secure, and none of them was exercised by an empirical field here.
