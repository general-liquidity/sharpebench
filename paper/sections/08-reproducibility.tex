\section{Reproducibility statement}\label{sec:repro}

The Rust workspace lists fourteen members: twelve packages under \texttt{crates/}, \texttt{xtask} and the reference-agent example. The twelve packages under \texttt{crates/} are eleven library packages plus the \texttt{sharpebench} CLI binary; a thirteenth crate directory, the published PyO3 binding, is excluded from the workspace because maturin builds it separately. The project code is licensed MIT and Apache-2.0 and published to crates.io, npm and PyPI, with a pinned toolchain and lockfile; the code license does not license the frozen data (\cref{app:datasheet}). Each of the twelve workspace package roots under \texttt{crates/} declares \texttt{forbid(unsafe\_code)}. The excluded PyO3 package is the disclosed exception: generated FFI glue expands to unsafe operations and its root does not make that declaration. Every historical dataset in \cref{tab:data} is committed with a SHA-256 sidecar; its fetch or derivation script identifies how the exact evidence bytes were obtained, but the online FRED fetches are not a permission to repeat the service use under current terms. Every figure in this paper is produced by a committed script from the kernel's own formulas, and every table is produced by the commands in \cref{app:commands} from the committed data. Golden fixtures pin the full ranked output of two fields at full floating-point precision and those two fixtures are checked on Linux, macOS and Windows. A WebAssembly parity test checks the corresponding native and WebAssembly results on its configured CI host; it is not evidence for every input on every platform. The self-audit fails if any of its nine claimed defenses regresses, and the Sybil case additionally fails if the attack stops reproducing with clone collapse switched off.

The empirical and engineering versions are different strata. The performance records, tables and figures are the v0.9.0 evidence snapshot described in \cref{app:commands}; they were not regenerated after the code hardening documented in this revision. The exact current source and artifact scope is delegated to \texttt{paper/evidence/provenance.json} rather than copied into prose as a version or test count that will drift. Continuous integration covers release rehearsal, formatting and lints, workspace and Python tests, cross-platform determinism, the live container boundary, self-audit, realism, supply-chain policy, documentation and paper provenance; separate workflows cover npm and the forward-arena state. \texttt{paper-provenance} runs \texttt{check-provenance.py}, so a manifest that no longer matches the tree fails rather than sitting stale. The live Docker tests run only in the explicit sandbox job and have the narrower interpretation stated in \cref{sec:limitations}.

The model-agent build preserves the evaluator boundary. SharpeArena owns point-in-time interaction, strict decision validation, execution and append-only cell journals; validated file artifacts then cross into SharpeBench for field-level scoring. SharpeBench does not depend on the full SharpeArena package. The compatibility examples and bridge are tested without admitting a model result, and any future field must bind its model artifact, inference runtime, prompt and scaffold, decoding configuration, raw responses and fault classes. A model's output is not covered by the environment's byte-determinism claim.

The prospective path uses the same package boundary. SharpeArena freezes contracts and writes append-only \texttt{sharpe.forecast-evidence.v1} ledgers; SharpeBench revalidates and scores the raw predictions independently. The deterministic tutorial fixes two synthetic producer files and the complete expected report. The Lean project under \texttt{formal/} models common-support intersection, forecast-report rank isolation, the ordered fixed-point Holm step and the finite-bootstrap plus-one correction. These theorems are about a deliberately small mathematical model, not an extraction of Rust semantics; executable conformance and mutation tests are the bridge to the implementation. No current-model result is admitted through either product surface.

No large language model is a component of the benchmark or of any result in this paper; the kernel has no judge. Language models were used to draft and edit prose; no citation in the bibliography was generated by one, and every arXiv entry was checked against its abstract page.
