\section{Reproducibility statement}\label{sec:repro}

The Rust workspace lists fourteen members: twelve packages under \texttt{crates/}, \texttt{xtask} and the reference-agent example. The twelve packages under \texttt{crates/} are eleven library packages plus the \texttt{sharpebench} CLI binary; a thirteenth crate directory, the published PyO3 binding, is excluded from the workspace because maturin builds it separately. The project code is licensed MIT and Apache-2.0 and published to crates.io, npm and PyPI, with a pinned toolchain and lockfile; the code license does not license the frozen data (\cref{app:datasheet}). All twelve production Rust package roots declare \texttt{forbid(unsafe\_code)}. Every historical dataset in \cref{tab:data} is committed with a SHA-256 sidecar; its fetch or derivation script identifies how the exact evidence bytes were obtained, but the online FRED fetches are not a permission to repeat the service use under current terms. Every figure in this paper is produced by a committed script from the kernel's own formulas, and every table is produced by the commands in \cref{app:commands} from the committed data. Golden fixtures pin the full ranked output of two fields at full floating-point precision and those two fixtures are checked on Linux, macOS and Windows. A WebAssembly parity test checks the corresponding native and WebAssembly results on its configured CI host; it is not evidence for every input on every platform. The self-audit fails if any of its nine claimed defenses regresses, and the Sybil case additionally fails if the attack stops reproducing with clone collapse switched off.

The empirical and engineering versions are different strata. The performance records, tables and figures are the v0.9.0 evidence snapshot described in \cref{app:commands}; they were not regenerated after the code hardening documented in this revision. The current engineering tree is on the v0.15.0 development line, and its exact source and artifact scope is delegated to \texttt{paper/evidence/provenance.json} rather than copied into the prose. The main workflow currently defines eleven jobs: \texttt{release-rehearsal}, \texttt{check}, \texttt{test}, \texttt{python}, \texttt{determinism}, \texttt{sandbox}, \texttt{audit}, \texttt{realism}, \texttt{supply-chain}, \texttt{docs} and \texttt{paper-provenance}; \texttt{test} and \texttt{determinism} fan out across Linux, macOS and Windows, and separate npm and forward-arena workflows cover their own surfaces. \texttt{paper-provenance} runs \texttt{check-provenance.py}, so a manifest that no longer matches the tree fails rather than sitting stale. On the audited local tree, \texttt{cargo test --workspace} reports 653 passed, 0 failed and 11 ignored: ten live Docker tests reserved for the \texttt{sandbox} job and one local open-weight compatibility test that needs the sibling SharpeArena package. The Docker evidence has the narrower interpretation stated in \cref{sec:limitations}.

The local-agent build preserves the evaluator boundary. SharpeArena owns point-in-time interaction, strict decision validation, execution and append-only cell journals; a validated file artifact then crosses into SharpeBench for field-level scoring. SharpeBench does not depend on the full SharpeArena package. The local compatibility example and Arena bridge are tested without admitting a model result, and any future field must bind exact model/checkpoint and quantization digests, inference-engine and scaffold versions, cadence and thinking settings, raw response hashes, token counts and fault classes. A model's output is not covered by the environment's byte-determinism claim. An end-to-end Gordon review informed the threat model, but no Gordon runtime, memory, strategy generator or broker layer is imported; a Gordon-like heavy scaffold remains a future paired treatment rather than a hidden default.

No large language model is a component of the benchmark or of any result in this paper; the kernel has no judge. Language models were used to draft and edit prose; no citation in the bibliography was generated by one, and every arXiv entry was checked against its abstract page.
